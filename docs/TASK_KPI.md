# Задачи в расчёте KPI

В настройках Bitrix24 выделен блок «Задачи: обучение и переработки».

- Обучение: поле `UF_TASK_BONUS`, значение «Да» — `783`, «Нет» — `784`. Значения проверены через API портала 07.09.2026. Месяц определяется по крайнему сроку задачи, согласно уточнению пользователя. Получатель — исполнитель; ставка берётся из версии правил премий. Статус завершения не является дополнительным условием.
- Переработки: проект `192` («Отдел внедрения - переработки»), отделы исполнителей `20` (внедрение) и `33` (разработка 1С). Отбор по крайнему сроку в месяце, границы в часовом поясе Москвы. Ручное поле задаётся отдельно, значения в часах; по умолчанию приоритет у заполненного ручного поля, включая ноль. Таймер `TIME_SPENT_IN_LOGS` возвращает секунды. Код ручного поля пока не обнаружен, поэтому используется таймер.
- Переработки сохраняются отдельными строками `overtime_hours` с исходной задачей и источником часов. Это учёт количества часов, без начисления оплаты по окладу.
- Часы задач читаются из `task.elapseditem.getlist`. Месяц определяется по `CREATED_DATE` записи времени, получатель — её `USER_ID`. В расшифровке показываются задачи, связанные через `UF_CRM_TASK` со сделками воронок `Тех интеграция`, `Внедрение`, `Сопровождение` и `CR Start`. В KPI и оплату входят только задачи допустимого сопровождения; остальные часы сохраняются как справочные строки с нулевым начислением. Если у задачи есть допустимая связь с сопровождением, она имеет приоритет и запись времени показывается один раз. Если связанное со сделкой сопровождения внедрение найдено, оно должно быть успешно завершено; активное сопровождение без найденной связи учитывается с предупреждением диагностики — так же, как бонус текущего клиента. После проигрыша сопровождения записи позднее даты закрытия не учитываются. Записи одной задачи одного сотрудника агрегируются; количество часов округляется до сотых, а часы сопровождения умножляются на версионируемую ставку `support_hour_rate`.

При новом расчёте задачи читаются из Bitrix24. Снимки сохраняются в детализации версии расчёта; повторный расчёт создаёт новую версию. Старые версии автоматически не изменяются. Ошибка получения задач прерывает расчёт. Ручные события обучения по-прежнему учитываются отдельно: ранее внесённые вручную начисления следует сверить перед переходом на автоматическое получение задач.

Проверка 07.09.2026: за сентябрь найдена одна задача обучения и четыре задачи переработок на 4,25 часа. Полный расчёт проверен с откатом транзакции: пять строк задач содержат ID и исходные данные. Доступ к задачам сопровождения и методу `task.elapseditem.getlist` подтверждён: задача `162217` сделки `39203` содержит 22 записи времени, общий таймер — 91796 секунд.

Обновление OAuth использует `BITRIX_OAUTH_TOKEN_URL` (по умолчанию `https://oauth.bitrix24.tech/oauth/token/`). Запрос к `/oauth/token/` самого коробочного портала возвращал HTML. Основание: [продление токенов Bitrix24](https://apidocs.bitrix24.ru/settings/oauth/auto-renewal.html).

Проверки: `python -m unittest discover -s backend/tests -p test_task_kpi.py` при настроенном `PYTHONPATH=backend/src` и окружении backend; `npm run build` в frontend.
